# Концертные страницы и жанры — 23.09.2026

## Откуда берутся события и почему не хватало жанров

Новая афиша получает события через GigsBot API (`city_web`, `concerts_web`, `concert_page`). Эти обработчики не создают отдельные записи концертов WordPress: ответы сохраняются в transient-кэше. В проверенной выгрузке нет ни жанров, ни стабильного идентификатора события.

Жанр до исправления искался в поле `genre_group` локальной карточки артиста. Среди 10 039 опубликованных артистов 1 108 имели заполненный жанр, 3 952 — значение `0`, ещё 4 979 — не имели поля. Поэтому отсутствие жанра в новой афише не означает, что импорт потерял метку события.

Старые концертные записи WordPress содержат рубрики жанров. Они используются как дополнительный источник, без изменения старой календарной афиши.

## Определение и показ жанров

1. Явно выбранный жанр артиста имеет приоритет.
2. При пустом поле или `0` используются жанровые рубрики опубликованных старых концертов этого артиста. Имя берётся из `group_afisha`, при его отсутствии — из заголовка старой записи.
3. Сопоставление учитывает регистр, пробелы, HTML-сущности, внешние кавычки и `ё`/`е`. Нечёткого подбора по похожим именам нет.
4. Из автоматического наследования исключены форматы «Фестивали», «Open Air», «SALE», «Детям», «Шоу», «Балет»: разовое участие не определяет жанр артиста. Явный выбор редактора сохраняет приоритет.
5. Поддерживаются несколько исторических жанров. Событие участвует в соответствующих фильтрах, но не дублируется в общей выдаче. Пустые жанровые фильтры не выводятся.
6. Если у одноимённых карточек разные явно заданные жанры, автоматический результат оставляется пустым для проверки редактором.

Жанры отображаются в общей афише, карточках артиста и площадки, на странице отдельного концерта. Кэш соответствий обновляется после сохранения записей, изменения `genre_group`/`group_afisha`, рубрик и связей с ними.

## Сохранение карточки артиста

Блок полей появляется при выборе рубрики артиста, в том числе у новой записи. Проверяются отдельный nonce, право редактирования, принадлежность записи рубрике артистов, автосохранение и ревизии. Отсутствующее в запросе поле жанра больше не затирает существующее. Принимаются только предусмотренные жанры либо `0` («Автоматически из старой афиши»). Строки проходят соответствующую очистку.

## Расхождение списка и страницы концерта

У Даниила Крамера на 24.09.2026 метод `city_web` возвращал «Огород» и билетную ссылку Afisha, а методы артиста и отдельного концерта — «Академ Джаз Клуб», время 20:00 и ссылку Kassir. Расхождение воспроизводилось в свежих ответах API, не только в кэше.

**Уточнение первоначального аудита:** это одно физическое место. [Afisha](https://www.afisha.ru/concert/daniil-kramer-trio-2217979/) описывает «Академ-джаз-клуб» внутри ресторана «Огород»; [Kassir](https://msk.kassir.ru/koncert/djaz-klub-akademicheskiy/daniil-kramer-trio_2026-09-24) указывает тот же адрес — проспект Мира, 26, стр. 1. Отображаемое название проверенных московских вариантов унифицировано: «Академ Джаз Клуб (Огород)». Исходные значения API не переписываются.

Общая причина возможной подмены предложения исправлена отдельно: ссылки из афиши, артиста и площадки сохраняют выбранное предложение параметром `event`. Ключ учитывает артиста, город, дату/сеанс, площадку, источник и конечный адрес покупки. Изменение цены, картинки или внешней партнёрской обёртки не меняет ключ.

Страница сначала использует сохранённое выбранное предложение, затем ищет совпадение в актуальных источниках. При явно заданном ключе другое предложение не подставляется. Старые ссылки без параметра продолжают работать; при нескольких подходящих событиях пользователь перенаправляется к афише артиста. Недоступность источника возвращает 503 с `Retry-After`, отсутствие события — оформленную 404. Canonical выбранного предложения содержит его параметр.

Ограничение: у API нет стабильного ID. Наш ключ вычисляется из данных предложения; изменение этих данных меняет ключ. Выбранное предложение хранится сутки, после истечения кэша его можно восстановить только из доступных источников. Постоянная доступность старых предложений не гарантируется. Время, отсутствующее в исходном предложении, не придумывается.
